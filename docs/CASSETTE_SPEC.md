# CassetteCraft Specification

This document defines the schema, structure, and determinism rules for cassette files generated by cassettecraft.

---

## 1. Storage Formats

`cassettecraft` supports both YAML (`.yaml`, `.yml`) and JSON (`.json`) formats. YAML is the default format because it produces readable git diffs during code reviews.

---

## 2. Cassette Schema (YAML)

A cassette file contains metadata and an ordered list of recorded interactions:

```yaml
version: 1
recorded_at: "2026-11-10T12:00:00Z"
recorded_by: "cassettecraft/v1.0"
interactions:
  - id: "int_01h8x123abc456"
    recorded_at: "2026-11-10T12:00:01Z"
    request:
      method: "POST"
      url: "https://api.stripe.com/v1/customers"
      headers:
        Authorization: "Bearer [REDACTED_STRIPE_KEY]"
        Content-Type: "application/x-www-form-urlencoded"
      body: "email=user%40example.com&name=Test+User"
      body_hash: "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
    response:
      status: 200
      status_text: "OK"
      headers:
        Content-Type: "application/json"
        Stripe-Version: "2024-06-20"
      body: |
        {
          "id": "cus_N4ABC1234567890",
          "object": "customer",
          "created": 1700000000,
          "email": "user@example.com",
          "name": "Test User"
        }
      body_hash: "a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e"
      latency_ms: 184
```

---

## 3. Schema Field Definitions

### Root Level
- `version` (integer, required): Schema version number. Currently `1`.
- `recorded_at` (string, ISO 8601 timestamp): UTC timestamp when the cassette was first created or updated.
- `recorded_by` (string): Tool name and version.
- `interactions` (array, required): Ordered list of HTTP request and response pairs.

### Interaction Object
- `id` (string, required): Deterministic unique identifier for the interaction.
- `recorded_at` (string, ISO 8601 timestamp): Timestamp of the specific call.
- `request` (object, required):
  - `method` (string): HTTP method (e.g. `GET`, `POST`, `PUT`, `DELETE`).
  - `url` (string): Full URL including protocol, host, path, and query string.
  - `headers` (map[string]string): HTTP request headers with sensitive headers redacted.
  - `body` (string, optional): String representation of the request payload.
  - `body_hash` (string, optional): SHA-256 hex digest of the raw request body.
- `response` (object, required):
  - `status` (integer): HTTP status code (e.g. `200`, `201`, `404`).
  - `status_text` (string): Standard HTTP status text (e.g. `OK`, `Created`).
  - `headers` (map[string]string): HTTP response headers.
  - `body` (string): Response payload. JSON payloads are formatted with standard 2-space indentation.
  - `body_hash` (string, optional): SHA-256 hex digest of the raw response body.
  - `latency_ms` (integer): Latency observed from upstream in milliseconds.

---

## 4. Determinism Rules

To prevent noisy git diffs, `cassettecraft` enforces the following serialization rules:

1. **Header Sorting**: Header keys are sorted alphabetically in ascending order.
2. **Header Normalization**: Common variable headers like `Date`, `Age`, and `X-Request-Id` are excluded from recorded cassettes unless explicitly preserved.
3. **JSON Normalization**: When `Content-Type` is `application/json`, keys are formatted predictably and trailing whitespaces are removed.
4. **Stable Indentation**: YAML is output with consistent 2-space indentation and newline formatting.
